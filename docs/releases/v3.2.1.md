# MasCloner v3.2.1 recovery-bundle patch

v3.2.0's bridge can fail during pre-update backup verification when an
installation contains normal Python cache files. Its inventory counted files
that the archive omitted. v3.2.1 uses one inclusion rule for both and adds a
regression test. The published `v3.2.0` tag and assets remain unchanged.

The attempted v3.2.0 upgrade on the reviewed VM failed at transaction phase
`validated`, before services were stopped or application files were replaced.
The operator confirmed both API/UI services remained active and `.commit_hash`
still identified `7f22b48bd2c159d998120a39fd672e818910973a`.

## Existing v3.0 installation

The previous failed transaction ended in phase `validated`, before any
installation mutation, so it does not block a retry. Once the
[v3.2.1 GitHub release](https://github.com/ali-raaed31/mascloner/releases/tag/v3.2.1)
is published, run these commands in a new directory on the VM:

```bash
mkdir -p ~/mascloner-v3.2.1 && cd ~/mascloner-v3.2.1
curl -fL -O https://github.com/ali-raaed31/mascloner/releases/download/v3.2.1/upgrade_v3_2.py
curl -fL -O https://github.com/ali-raaed31/mascloner/releases/download/v3.2.1/mascloner-3.2.1.tar.gz
curl -fL -O https://github.com/ali-raaed31/mascloner/releases/download/v3.2.1/mascloner-3.2.1.tar.gz.sha256
sudo python3 ./upgrade_v3_2.py --release-archive ./mascloner-3.2.1.tar.gz \
  --sha256 "$(cut -d ' ' -f1 ./mascloner-3.2.1.tar.gz.sha256)"
```

The bridge checks the archive digest before loading code from it. It announces
the recovery-bundle phase, which may take several minutes on this VM; services
stay online until the bundle is verified. On success it prints `Installed
3.2.1 (<commit>)`. Confirm the installed identity with
`cat /srv/mascloner/VERSION /srv/mascloner/.commit_hash`.

Do not run the old installed `mascloner update` command to reach v3.2.1. Do
not rerun the v2-to-v3 `mascloner migrate --apply` command on the already-cut
over VM. The bridge creates a recovery bundle, installs dependencies and code,
checks migrations and service health, and prints the installed version on
success. If it reports a failed recovery after stopping services, stop and
inspect the transaction record under `/var/backups/mascloner/transactions/`
before retrying. Use `mascloner update` for releases after the bridge has
successfully installed v3.2.1.
