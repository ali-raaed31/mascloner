# MasCloner v3.2.1 recovery-bundle patch

v3.2.0's bridge can fail during pre-update backup verification when an
installation contains normal Python cache files. Its inventory counted files
that the archive omitted. v3.2.1 uses one inclusion rule for both and adds a
regression test. The published `v3.2.0` tag and assets remain unchanged.

The attempted v3.2.0 upgrade on the reviewed VM failed at transaction phase
`validated`, before services were stopped or application files were replaced.
The operator confirmed both API/UI services remained active and `.commit_hash`
still identified `7f22b48bd2c159d998120a39fd672e818910973a`.

## Existing v3.0 installation

Use the `upgrade_v3_2.py` bridge and the `mascloner-3.2.1.tar.gz` archive from
the [v3.2.1 GitHub release](https://github.com/ali-raaed31/mascloner/releases/tag/v3.2.1).
The bridge's required `--sha256` value is printed in the release notes; no
manual checksum calculation is needed. The bridge will announce the recovery
bundle phase. On this VM it may take several minutes and services remain online
until that bundle has been verified.

Do not run the old installed `mascloner update` command to reach v3.2.1. Do
not rerun the v2-to-v3 `mascloner migrate --apply` command on the already-cut
over VM. The bridge creates a recovery bundle, installs dependencies and code,
checks migrations and service health, and prints the installed version on
success. If it reports a failed recovery, stop and inspect the transaction
record under `/var/backups/mascloner/transactions/` before retrying.
