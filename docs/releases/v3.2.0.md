# MasCloner v3.2.0 release candidate

v3.2.0 is a release candidate until the qualification record in
[`v3.2.0-qualification.md`](v3.2.0-qualification.md) is complete. Do not
create the `v3.2.0` Git tag or GitHub release before every required gate has
evidence attached.

## Scope

This release repairs the upgrade path from the installed v3.0 CLI updater and
the v3.1 UI/API contract defects found during the upgrade review. It also makes
legacy v2-to-v3 cutover and recovery operations fail safely.

The release artifact is an immutable `mascloner-3.2.0.tar.gz` archive. It has
one top-level `mascloner-release/` directory and contains `RELEASE.json` with
the release version, immutable revision, and a checksum for every payload file.
The payload includes `VERSION`, `.commit_hash`, requirements, application code,
migrations, systemd units, and the updater implementation.

## Build a reviewable candidate artifact

These commands build a candidate from a clean checkout of one immutable commit.
They do not create a tag or publish a release. Run them only after the final
review has identified the candidate commit, then keep the resulting archive and
checksum evidence with the qualification record.

The explicit `git archive` path list is intentional. It excludes local
`.venv`, `data`, `etc`, `.env`, `.env.production`, databases, rclone
configuration, and every other untracked workspace file. Do not replace it
with an archive of the working directory.

```bash
set -euo pipefail
RELEASE_COMMIT='REPLACE_WITH_FULL_40_CHARACTER_QUALIFIED_COMMIT'
RELEASE_WORKDIR="$(mktemp -d)"

git rev-parse --verify "${RELEASE_COMMIT}^{commit}"
git clone --no-local --no-checkout . "$RELEASE_WORKDIR/checkout"
git -C "$RELEASE_WORKDIR/checkout" checkout --detach "$RELEASE_COMMIT"
test "$(git -C "$RELEASE_WORKDIR/checkout" rev-parse HEAD)" = "$RELEASE_COMMIT"

mkdir -p "$RELEASE_WORKDIR/stage/mascloner-release"
git -C "$RELEASE_WORKDIR/checkout" archive --format=tar "$RELEASE_COMMIT" \
  -- app ops alembic alembic.ini requirements.txt VERSION \
  | tar --extract --file=- --directory="$RELEASE_WORKDIR/stage/mascloner-release"

test "$(cat "$RELEASE_WORKDIR/stage/mascloner-release/VERSION")" = "3.2.0"
if find "$RELEASE_WORKDIR/stage/mascloner-release" -type l -print -quit | grep -q .; then
  exit 1
fi
```

Create the immutable release manifest from the clean checkout, then make the
archive and separate bridge-script checksum:

```bash
python3 "$RELEASE_WORKDIR/checkout/ops/scripts/build_release_manifest.py" \
  "$RELEASE_WORKDIR/stage/mascloner-release" \
  --revision "$RELEASE_COMMIT"

tar --create --gzip \
  --file="$RELEASE_WORKDIR/mascloner-3.2.0.tar.gz" \
  --directory="$RELEASE_WORKDIR/stage" mascloner-release
(
  cd "$RELEASE_WORKDIR"
  sha256sum mascloner-3.2.0.tar.gz > mascloner-3.2.0.tar.gz.sha256
)

cp "$RELEASE_WORKDIR/checkout/ops/scripts/upgrade_v3_2.py" \
  "$RELEASE_WORKDIR/upgrade_v3_2.py"
(
  cd "$RELEASE_WORKDIR"
  sha256sum upgrade_v3_2.py > upgrade_v3_2.py.sha256
)
```

Validate the archive before it is used by a fixture or operator. This confirms
the single top-level directory, rejects unexpected operational data, and runs
the same complete inventory validation required by the updater:

```bash
test "$(tar --list --gzip --file="$RELEASE_WORKDIR/mascloner-3.2.0.tar.gz" \
  | cut -d/ -f1 | sort -u | wc -l)" -eq 1
test "$(tar --list --gzip --file="$RELEASE_WORKDIR/mascloner-3.2.0.tar.gz" \
  | cut -d/ -f1 | sort -u)" = "mascloner-release"
if tar --list --gzip --file="$RELEASE_WORKDIR/mascloner-3.2.0.tar.gz" \
  | grep -E '(^|/)(\.venv|data|etc|\.env|\.env\.production|rclone\.conf)(/|$)|\.db$'; then
  exit 1
fi

mkdir "$RELEASE_WORKDIR/verify"
tar --extract --gzip --file="$RELEASE_WORKDIR/mascloner-3.2.0.tar.gz" \
  --directory="$RELEASE_WORKDIR/verify"
(
  cd "$RELEASE_WORKDIR/verify/mascloner-release"
  env PYTHONDONTWRITEBYTECODE=1 python3 -c \
    'from pathlib import Path; from ops.cli.transaction import validate_release; print(validate_release(Path.cwd()))'
)
(
  cd "$RELEASE_WORKDIR"
  sha256sum --check mascloner-3.2.0.tar.gz.sha256
  sha256sum --check upgrade_v3_2.py.sha256
)
```

Record the candidate commit and both digests in the qualification record. The
candidate becomes a release only when its qualification gates pass and the tag
is created from this exact commit.

## One-time bridge from an installed v3.0 updater

Use this procedure for an installation whose updater predates v3.2, including
the production-like installation at `7f22b48`. The old `mascloner update`
command is not the v3.2 bridge: it cannot install a coherent v3.2 runtime.

Before the maintenance window, obtain these three files from the same qualified
release record:

- `upgrade_v3_2.py`
- `upgrade_v3_2.py.sha256`
- `mascloner-3.2.0.tar.gz` and `mascloner-3.2.0.tar.gz.sha256`

Verify the bridge script before executing it. Substitute the published digest
file names and local download directory as needed.

```bash
cd /path/to/release-files
sha256sum --check upgrade_v3_2.py.sha256
sha256sum --check mascloner-3.2.0.tar.gz.sha256
```

The bridge checks the archive digest before extraction or code import, verifies
the archive layout, and checks the release inventory, version, and revision.
It also checks `/srv/mascloner/.venv/bin/python` before services or packages
are changed. It requires Python 3.10 or later. The reviewed production VM
reported Python 3.12.3, which satisfies this prerequisite; run the preflight
again for the actual maintenance window.

Run the verified bridge as root:

```bash
sudo python3 /path/to/upgrade_v3_2.py \
  --release-archive /path/to/mascloner-3.2.0.tar.gz \
  --sha256 "$(cut -d ' ' -f1 /path/to/mascloner-3.2.0.tar.gz.sha256)" \
  --install-dir /srv/mascloner \
  --backup-dir /var/backups/mascloner \
  --user mascloner
```

On success it prints `Installed 3.2.0 (<immutable commit>)`. Confirm that
`/srv/mascloner/VERSION` and `/srv/mascloner/.commit_hash` match that printed
identity, then complete the post-upgrade checks in the qualification checklist.

The bridge creates a verified recovery bundle before it changes the installed
release. If an update phase fails, it restores that bundle and reports whether
recovery completed. For an operator-initiated recovery after a completed
upgrade, use the exact bundle created for that attempt:

```bash
sudo mascloner rollback \
  /var/backups/mascloner/mascloner-recovery-<UTC-timestamp>.tar.gz --yes
```

Only verified `mascloner-recovery-*` bundles are accepted. Preserve the bridge
output and the transaction record under
`/var/backups/mascloner/transactions/` with the release qualification record.

## Subsequent v3.2+ updates

After the one-time bridge has installed v3.2 or later, use the CLI updater with
an immutable release archive and its published 64-character SHA-256 digest.
`sudo` does not preserve ordinary shell environment variables, so pass these
values through `sudo env` as part of the command:

```bash
sudo env \
  MASCLONER_RELEASE_ARCHIVE=/path/to/mascloner-3.2.0.tar.gz \
  MASCLONER_RELEASE_SHA256=<64-hex-digest> \
  mascloner update --yes
```

The updater verifies the archive digest before extraction and verifies the
complete `RELEASE.json` inventory before changing the installation. For a
disconnected qualification fixture only, a previously verified unpacked
artifact may be supplied with `MASCLONER_RELEASE_DIR=/path/to/artifact`; it is
still subject to the complete release-manifest validation. Production updates
use the archive form above.

## Live-instance migration decision

The reviewed live VM already has Alembic revision `20250101_000003`, the v3
columns, nonempty SQLite SyncRoute paths, and canonical terminal run statuses.
It needs no repair migration based on the captured readiness report. Do not run
`mascloner migrate --apply` again on that cut-over VM.

## Tag and publish gate

The release manager may tag the exact qualified commit only after the completed
checklist records the candidate commit, release archive and bridge checksums,
test results, upgrade rehearsal evidence, recovery rehearsal evidence, and
operator go/no-go decision.

```bash
git tag -a v3.2.0 <qualified-commit> -m "MasCloner v3.2.0"
git push origin v3.2.0
```

Create the GitHub release from that same tag and attach the release archive,
checksum files, bridge script, bridge-script checksum, and redacted
qualification record.
